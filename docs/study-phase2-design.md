## 一、设计理念（基于 Naval 财富框架）

### 1.1 核心跨越

第一期实现了数据沉淀和画像生成，但仍有两个局限：

1. **依赖用户主动触发**：用户要手动说"开始学习"，机器人才能介入
2. **缺乏真实环境感知**：只知道时长，不知道用户是否真的在专注（可能挂机、走神、玩手机）

第二期的核心突破：**从"被动计时器"变成"主动观察者 + 行为教练"**。

- **专长深化**：不仅识别时间规律，还识别行为模式（坐姿、专注度、环境干扰）
- **杠杆升级**：引入视觉识别（摄像头），让机器人"看到"用户状态，实时反馈
- **社交杠杆**：引入家庭内"学习伙伴"概念（妈妈陪孩子、姐姐带弟弟），通过关系放大效果
- **资产扩展**：沉淀的不仅是"我的学习数据"，还有"我们家的学习文化"

### 1.2 Naval 框架对照

| 维度 | 第一期 | 第二期 |
|------|--------|--------|
| **专长** | 识别时间规律 | 识别行为模式（坐姿、环境） |
| **杠杆** | 数据分析（代码） | 视觉识别（AI）+ 家庭关系 |
| **复利** | 个人画像积累 | 家庭学习文化沉淀 |
| **资产** | 个人学习报告 | 行为改进方案 + 家庭协同记录 |

### 1.3 红线重申（设计约束）

**来自第0期的三条红线保持不变：**

1. ✅ **陪伴，不监控**：孩子知情、可关闭、帮她而非盯她
2. ✅ **辅助，不替代**：提醒改坐姿，不是替她端正身体
3. ✅ **记录，不惩罚**：记下走神次数，但不"扣分"或"报告给家长"

**第二期新增红线：**

4. ✅ **家庭内，不社交化**：数据仅家庭成员可见，不做排行榜、不对外比较
5. ✅ **建议，不强制**：机器人给改进建议，但用户可选择忽略
6. ✅ **隐私第一**：摄像头仅本地分析，图像不保存、不上传

## 二、功能架构

### 2.1 视觉感知层（新增）

#### 模块 A：姿态检测器（`vision/posture.py`）

**技术选型**：

- **库**：MediaPipe Pose（轻量级，CPU 可跑，延迟 < 50ms）
- **检测频率**：每 5 秒采样 1 帧（降低资源消耗）
- **输出指标**：
  - 头部前倾角度（正常 < 15°，低头玩手机 > 30°）
  - 肩膀对称度（驼背时左右高度差 > 5cm）
  - 距离屏幕过近（人脸框宽度占画面 > 40%）

**关键函数**：

```python
def analyze_posture(frame: np.ndarray) -> dict:
    """
    分析单帧姿态，返回：
    {
        "head_tilt_angle": 12.5,      # 头部前倾角度
        "shoulder_symmetry": 0.95,    # 肩膀对称度（1.0 = 完美）
        "distance_score": 0.8,        # 距离得分（0-1，越高越好）
        "posture_quality": "good",    # good | fair | poor
        "warnings": ["头部前倾"]       # 具体问题列表
    }
    """

def detect_distraction(frame: np.ndarray) -> dict:
    """
    检测分心行为：
    {
        "looking_away": False,        # 视线离开屏幕
        "phone_detected": False,      # 检测到手机（通过手势）
        "person_absent": False,       # 人离开座位
        "focus_score": 0.9            # 专注度得分（0-1）
    }
    """
```

**提醒策略**：

- 连续 3 次（15 秒）检测到同一问题 → 柔性提醒："注意坐姿，头抬高一点"
- 10 分钟内已提醒过 → 静默，避免骚扰
- 用户说"知道了"或手势回应 → 记录为"已接受建议"

#### 模块 B：环境分析器（`vision/environment.py`）

**检测维度**：

- **光线充足度**：画面亮度均值，判定是否需要开灯
- **背景嘈杂度**：画面运动幅度，判定是否有人走动干扰
- **桌面整洁度**：物体检测 + 占比，提醒"桌面有点乱"

**关键函数**：

```python
def analyze_environment(frame: np.ndarray) -> dict:
    """
    {
        "lighting": "dim",           # bright | normal | dim
        "noise_level": "quiet",      # quiet | moderate | noisy
        "desk_clutter": 0.3,         # 0-1，0 = 很整洁
        "suggestions": ["建议开灯"]
    }
    """
```

## 三、技术实施

### 3.1 视觉处理流水线

```
摄像头帧 (30fps)
    ↓ 降采样
每 5 秒 1 帧
    ↓ MediaPipe Pose
姿态关键点 (33 个)
    ↓ 规则引擎
判定问题 + 计算得分
    ↓ 提醒逻辑
决策是否干预
    ↓ 数据库
写入 study_vision_events
```

**性能要求**：

- 单帧处理时间 < 50ms（CPU i5 可达成）
- 内存占用 < 200MB
- 不保存原始图像，只保存数值特征

### 3.2 隐私保护技术

#### 边缘计算架构

```
Mac mini（本地）
├─ 摄像头输入
├─ MediaPipe 推理（CPU）
├─ 特征提取（仅数值）
└─ SQLite 存储（无图像）

✅ 图像不保存
✅ 不上传云端
✅ 断网可用
```

#### 数据脱敏

```python
# 仅存储抽象特征，不存储可识别信息
{
    "head_tilt": 12.5,        # ✅ 存储
    "shoulder_symmetry": 0.9, # ✅ 存储
    "face_embedding": [...]   # ❌ 不存储（可识别）
    "raw_image": bytes        # ❌ 不存储
}
```

#### 用户控制

```python
# 配置项
ROBOT_VISION_ENABLED=false  # 默认关闭，需要明确开启
ROBOT_VISION_SAVE_STATS=true  # 是否保存统计数据
ROBOT_VISION_REMINDER=true    # 是否允许姿态提醒
```

**前端开关**：

- "开启摄像头陪伴"按钮（默认关闭）
- "仅计时，不看摄像头"选项（回退到第0期模式）
- "查看本周视觉数据"（透明化数据收集）

## 六、风险与对策

### 6.1 技术风险

**风险1：视觉识别误判**

- 问题：光线不足或角度偏导致误报"姿态不良"
- 对策：
  - 增加"校准"步骤，让用户坐正时拍一张基准照
  - 提醒前二次确认（连续3次才提醒）
  - 提供"误报反馈"按钮，用户可标记

**风险2：性能瓶颈**

- 问题：Mac mini CPU 占用过高，影响其他任务
- 对策：
  - 降低采样频率（5秒 → 10秒）
  - 仅在"学习模式开启"时运行视觉模块
  - 提供"低性能模式"（关闭环境分析，只保留姿态检测）

### 6.2 隐私风险

**风险3：用户担心被监控**

- 问题：孩子觉得"一直被看着"，反感使用
- 对策：
  - 默认关闭摄像头，需要明确同意才开启
  - 每次开启时语音提示"摄像头陪伴已开启"
  - 提供"仅今天开启"选项，不持久化设置
  - 显示"绿色指示灯"表示摄像头工作中

**风险4：数据泄露**

- 问题：数据库被恶意访问
- 对策：
  - 数据库加密（SQLCipher）
  - 视觉特征不包含可识别信息
  - 提供"一键删除所有视觉数据"功能

### 6.3 教育风险

**风险5：过度依赖技术**

- 问题：孩子离开机器人就不会学习
- 对策：
  - 定期"自由学习日"，不开启任何提醒
  - 报告中强调"你的进步靠的是自己，机器人只是辅助"
  - 逐步降低干预频率（从每10分钟 → 每20分钟 → 每40分钟）

**风险6：家长过度解读数据**

- 问题：家长看到"专注度78%"就焦虑
- 对策：
  - 报告中强调"波动是正常的"
  - 提供"同龄参考区间"（但不做排名）
  - 避免使用"不合格""差"等负面词汇，改用"有进步空间"
