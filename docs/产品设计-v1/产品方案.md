# 家庭机器人 · 第一阶段产品设计 v1

状态：第一版运行页面已采用主要信息结构；完整家庭录入、语音与真实提醒场景还需验收。工作名暂用「阿伴」，名称、形象和配色均可调整。

## 产品定位与第一屏

第一阶段是放在家里的“会听、会回应、会提醒”的电脑端助手。打开页面，家人应在 3 秒内看见机器人、知道能说什么、知道今天是否有提醒。首页只承载三个核心动作：说话、查看/创建提醒、按需识别我。技术状态和事件日志收进设置，不占家庭用户的主屏。

运行页面现已加入机器人形象、四项导航、下一条提醒卡片，并将摄像头预览移入家庭页，默认关闭。提醒支持创建、修改、取消和保存前确认。成员管理、拍照预览/重拍/删除、隐私说明以及声音效果验收仍待实现。

## 信息结构

| 页面 | 家人看到的内容 | 主要动作 |
| --- | --- | --- |
| 陪伴（首页） | 机器人形象、当前状态、对话、今日下一条提醒 | 按住说话/输入、创建提醒、按需“认出我” |
| 提醒 | 今天/未来的提醒、状态、空状态 | 新建、确认、取消；语音创建与手动创建共用确认卡 |
| 家庭 | 已录入成员、录入说明 | 录入家人、重拍/删除、测试识别 |
| 设置 | 声音、自动朗读、摄像头权限状态、模型连接、故障信息 | 试听、调整、诊断 |

移动端优先采用底部三项导航「陪伴 / 提醒 / 家庭」，设置从右上角进入。桌面端采用左侧品牌区、中央对话区、右侧今日提醒。导航不应暴露“人脸算法”“事件日志”等工程术语。

## 机器人形象

选择“圆角桌面伙伴”作为第一版：暖白外壳、深青色面屏、两只清晰的眼睛、轻微微笑。它是可绘制的二维形象，不假装已有实体。视觉资产见 `robot-avatar.svg`。头像放在首页第一视觉位置，聊天气泡用缩小版头像署名。此阶段不需要循环播放真人视频，也不把摄像头画面当机器人形象。

五种状态共用同一形象，以眼睛、呼吸光和短文案变化：

| 状态 | 视觉/文案 | 触发 |
| --- | --- | --- |
| 待命 | 慢呼吸，`我在这里` | 默认 |
| 倾听 | 眼睛聚焦，麦克风光环，`正在听` | 用户明确开始录音 |
| 思考 | 小幅流动光点，`正在整理回答` | 请求发出到首字 |
| 说话 | 面屏波形，`正在说话` | 播放音频 |
| 提醒 | 暖橙色光环，`有一件事要提醒你` | 到期提醒 |

关闭动画/减少动态效果时，保留静态图与状态文字。未来桌面硬件可沿用脸部比例和状态语言，视频素材只在确有故事或开场内容时使用。

## 摄像头：按需出现的能力

首页可放次级入口「认出我」，家庭页放主入口「录入家人」。两者都先解释用途，再由用户点击“打开摄像头”触发浏览器授权；平时没有预览画面，也不暗示全天候识别。

录入流程：

1. 家庭页点击「录入家人」：说明用于打招呼与区分提醒对象，现有代码会在本机数据库保存识别特征，不长期保留原始照片；设计上应明确说明存储内容，并提供删除入口。
2. 输入称呼；随后明确点击「打开摄像头」。权限拒绝时解释浏览器设置路径，不出现空黑框。
3. 出现取景框与一句指引：一人入镜、脸部正对、光线充足。点击「拍摄」后立即停止视频轨道。
4. 显示抓拍预览、称呼；允许「重拍」或「确认录入」。检测不到脸/多人入镜时不保存，给明确纠正提示。
5. 成功后回到成员卡，可「测试识别」「重拍」「删除」。删除需二次确认，说明会移除本地特征；当前后端还没有删除成员接口，需在实现这页时补齐。

识别流程：点击「认出我」→ 开镜 → 拍一帧 → 关镜 → 显示 `你好，小明` 或 `还不认识你`；未知时提供录入入口。识别结果后续可连接个人提醒，但当前后端尚未完成该业务闭环，所以界面不可暗示自动绑定成功。

## 对话与提醒

首页输入框默认给具体示例「提醒我明天晚上八点半练琴」，常用建议最多三条。语音输入展示开始/结束、识别出的文字、失败重试；聊天模型回答和语音播放共用一个机器人消息。默认朗读开关放设置，当前播放时显示暂停/重播。

提醒无论从聊天还是表单进入，都用同一张确认卡：`明天 20:30 · 练琴`，两个动作「确认提醒」「修改」。保存成功后才显示完成状态，并进入提醒列表。到期后展示送达状态；播放失败显示待重试。复杂语句无法准确解析时，引导用户改用时间选择器，不让模型口头承诺“记下了”。

## 视觉规范草案

背景暖灰 `#F6F5F1`，主色深青 `#174747`，确认按钮青绿 `#167D72`，提醒强调橙 `#E89A6C`，文字 `#213532`。标题采用系统黑体，正文优先 16px；按钮触控高度至少 44px。卡片圆角 20–28px，阴影很浅。首页信息层级：机器人和一句状态 > 对话输入 > 下一条提醒 > 其他入口。桌面尺寸也不把系统诊断与用户任务并列。

## 已有能力与产品化缺口

| 项目 | 现在 | 下一步验收 |
| --- | --- | --- |
| 聊天 | DeepSeek Flash 流式回答 | 真实家庭对话连续 20 轮、失败恢复、误承诺检查 |
| 朗读 | 本地 Kokoro 中文语音 | 家人姓名、多音字、数字时间试听；播放控制一致 |
| 麦克风 | 浏览器语音识别 | 浏览器兼容性、噪声环境、权限拒绝、离线预期 |
| 提醒 | 简单规则句式；手动创建、确认、修改、取消；过期未播放状态提示 | 复杂时间、重复提醒、停机补发、扬声器/浏览器提醒体验 |
| 人脸 | 手动拍摄录入和单次识别接口 | 成员管理、删除、误识别/未知、隐私流程 |

设计预览文件 `prototype.html` 是静态原型：不连接真实摄像头、不保存提醒和照片，不替代当前服务。评审时重点看首页是否一眼能懂、摄像头入口是否自然、机器人形象是否适合家庭。
