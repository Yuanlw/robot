# 交互场景审计与语音策略设计 v1

日期：2026-11-13 · 触发：Chris 提问"什么时间是和机器人说话、什么时间是人和人对话，要不要唤醒词"
状态：设计提案，待 Chris 对 §5 决策点拍板后实施

---

## 0. 结论先行

1. **现状是按钮门控交互**：麦克风只在按住"开始说"时打开，机器人平时根本不在听——所以"误听人和人对话"这个问题**今天不存在**（这是按钮式的一个被低估的优点）。
2. **真正的"插话"问题在输出方向**：机器人的主动播报（提醒到点、学习计时、坐姿警告）完全不看场合——你在打电话、上网课、人和人正在对话，它照说。这是今天要修的。
3. **两个问题要分开解**：
   - 机器人自律（**不插人的话**）→ 统一语音通道 Speech Policy Engine，第一批就做；
   - 机器人听觉边界（**什么时候开始听人**）→ 唤醒词 + 视觉门控，属于"连续对话"立项（治"每次点按钮"的割裂），单独做。
4. **唤醒词结论：需要，但只在连续对话模式下需要**。按钮模式加唤醒词是画蛇添足；连续监听模式没有唤醒词是灾难。选型见 §3。

## 1. 社交场景盲区全景审计（多人场景之外的同类问题）

### A. 机器人打断人（输出方向）——今天就存在，最高优先级

| # | 场景 | 现状 | 证据 |
|---|---|---|---|
| A1 | 电话/网课/面对面交谈中，提醒到点 | 照样大声播 | reminder_loop 无任何场合感知 |
| A2 | **三条语音路径并发，机器人自己叠话** | afplay 无互斥，可同时响 | `voice.speak` 无锁（voice.py:264），4 个调用点：main.py:51（提醒）/:79（学习队列）/:416（试听）/:870（坐姿） |
| A3 | 家长在旁辅导（未入镜），坐姿警告打断教学互动 | 多人入镜已冻结（2adfd4b），但**画外音的家长和画面里的孩子**不触发多人冻结 | vision 多人检测只数画面内的脸 |
| A4 | 系统音量 0 / 静音时播报 | afplay 退出码 0 → 记"已送达"，实际没人听到 | **2026-11-13 实测：本机 volume=0、muted=true**——昨晚"提醒不正常"体感的可能组成部分 |
| A5 | 网课声音在放，机器人播报叠在讲课声上 | 无系统音频占用检测 | pmset 断言启发式待实机验证 |

### B. 误听人与人对话（输入方向）

| # | 场景 | 现状 | 结论 |
|---|---|---|---|
| B1 | 平时人和人聊天被机器人听到 | 不存在——麦克风默认关闭，按住才录 | ✓ 无需处理 |
| B2 | 按住说话时旁人同时说话 | ASR 混音，可能误指令 | 软件无解；缓解：贴近说、学习模式单人单桌假设 |
| B3 | 未来连续监听模式 | 未实现 | **唤醒词 + 视觉门控是前置条件**，没有它不许上连续监听（见 §3） |

### C. 话语归属（这句话算谁说的）

| # | 场景 | 现状 | 处理 |

| C1 | 袁玥绑定页面后，爸爸凑近说话 | 按袁玥身份处理（记忆、提醒归属全记她头上） | README 已如实声明该边界；短期靠"学习模式=单人单桌"场景假设成立 |

| # | 场景 | 现状 | 决策点 |

### E. 设备与环境冲突

- E1 静音/音量 0 = "送达但没听到"（即 v4 审计 P0-3）——osascript 检测已验证可行，第一批修；
- E2 启动变慢（face_recognition + mediapipe 加载，实测 ~20s）→ 重启窗口内提醒会延迟；reconcile 已兜底不丢，接受；
- E3 麦克风/摄像头占用冲突：识别流程与守护各自 getUserMedia，macOS 允许共享，暂无冲突证据，观察。

### F. 时间边界

- F1 安静时段目前只有 study_loop 的"8 点前"（自主播报），无家庭全局安静时段（午休、22:00 后）；
- F2 用户显式提醒不受安静时段限制（29a4cbb 已修正）——这是对的：7 点的药就该 7 点响；
- F3 建议：全局安静时段可配置（默认 22:00-07:00），只约束**机器人自主播报**，显式提醒照响。

## 2. 核心架构：统一语音通道（Speech Policy Engine）——第一批

**设计原则：机器人的每一句话都过同一条串行通道，说之前问一遍"现在能说吗"。**

```
输入源（带优先级）                     策略层（依序检查）                输出
─────────────────                    ──────────────────               ─────
P0 用户显式提醒到点    ──┐            1. 当前有话在说？→ 排队（互斥，根治 A2）
P1 交互应答(识别确认等) ──┤            2. 手动勿扰中？   → 转屏幕卡片，不发声
P2 学习定时(休息/回来)  ──┼──入队──►   3. 静音/音量0？   → 不播、不标送达、转屏幕卡片
P3 坐姿警告            ──┤            4. 系统音频占用？ → 延后重试（网课场景，第二批）
P4 学习柔性确认        ──┘            5. 安静时段？     → P0 照播，P2-P4 延后/转卡片
                                     6. 保鲜期检查     → 过期作废并记录（已有语义并入）
                                              │
                                              ▼
                                     串行 worker → afplay（一次只有一句）
                                              │
                                              ▼
                                     送达回执：delivered / deferred / muted / stale
                                     （mark_delivered 只在 delivered 时调用——P0-3 根治）
```

要点：
- **互斥**：全局单 worker 线程播 afplay，四个调用点全部改投通道，叠话物理不可能；
- **降级不丢失**：被挡下的播报转成页面卡片（听不见也看得见），提醒类仍按既有重试契约；
- **静音即未送达**：osascript 查 volume/muted（已验证可行），muted 时提醒不标 delivered、每 15s 重试照旧 + 页面横幅"我说话你没听到（系统静音）"；
- **勿扰**：页面按钮 + 语音"安静一小时"（Agent 工具 dnd_set），默认 60 分钟，到期自动解除；
- 现有 SpeechQueue 的保鲜/重试语义并入通道，study_loop 不再自己 drain。

改动面：新增 `app/speech.py`；main.py 四处调用点改投通道；settings 加 quiet_hours/dnd；前端加勿扰按钮+静音横幅。预计一次提交完成，测试以纯逻辑（策略判定函数）为主。

## 3. 唤醒词与连续对话（第三批，独立立项——治"割裂"的根治项）

### 3.1 结论

唤醒词**需要**，定位是"连续监听模式下，判断这句话是不是对我说的"的唯一可靠信号。没有它不许开连续监听（否则 B3 灾难：把人和人对话当指令）。

### 3.2 选型（按本项目约束评估）

| 方案 | 中文 | 许可/账号 | 运行位置 | 结论 |
|---|---|---|---|---|
| **sherpa-onnx KWS**（zipformer，wenetspeech 训练） | ✅ 支持自定义关键词 | Apache-2.0，无需账号 | 本地服务端，CPU 实时 | **首选**：与 kokoro-onnx 同生态、自定义唤醒词零成本 |
| Porcupine Web（WASM） | ✅（控制台训练中文词） | 商业，需 AccessKey 免费注册 | 浏览器内（音频不出浏览器，隐私最优） | 备选：隐私叙事最好，但引入外部账号依赖 |
| openWakeWord | ❌ 中文需自训（合成数据管线） | Apache | 本地 | 不选：中文自训成本高 |
| Snowboy | - | 已停维护(2020) | - | 排除 |

### 3.3 架构（立项后细化）

```
浏览器麦克风（仅学习/陪伴模式开启）
  → WebSocket 音频流到本机服务（音频不落盘、不出本机）
  → sherpa-onnx KWS 常驻检测唤醒词
  → 唤醒后：VAD 断句 → 现有 /api/stt（百炼）→ Agent → 统一语音通道播报
  → 视觉门控（我们独有的加强）：画面单人 + 脸朝屏幕才响应唤醒；
     朗读/背诵/和人说话（低头不看屏）不响应——把误唤醒再压一档
  → 按钮永久保留兜底；唤醒词引擎崩溃自动回退按钮模式
```

隐私声明（写进 README 和页面）：唤醒词检测期间音频只在内存流过本地模型，不录、不存、不上传；唤醒后的语音按现有 STT 隐私边界处理。

### 3.4 唤醒词候选

"阿伴阿伴"（4 音节、叠词、KWS 友好、与产品名一致）；备选"你好阿伴"。避免与家庭成员名字、常用词谐音。
